# Native soft-float Lua and OpenWrt C bindings

2026-10-26. Isolated AAPCS64-soft Lua5.1.5, Nixio, UCI, ubus and uloop now
execute on the actual BE6L no-FP CPU. Installed applications and libraries were
not replaced. This is a dependency experiment, not an APK feed or new firmware.

## Correct the runtime before building bindings

The first Lua test reached `sqrt(2)` but crashed in the following power operation.
Disassembly showed the generic libc `fma` calling itself: Clang had contracted
its internal multiply/add expressions into another `fma` call. A new independent
C regression reproduced status139 in both old static and dynamic runtimes.

The compiler wrapper now uses `-ffp-contract=off`. This preserves the generic
implementation's deliberate rounding steps and avoids introducing recursive
library calls. No source-level floating operation is replaced with an integer
approximation. Hardware capability reporting is unchanged.

New tests use volatile indirect calls to prevent constant folding. They cover
ordinary and cancelling fused operations, NaN, infinity, subnormal output, a
case distinguishing fused from separately rounded arithmetic, and `pow(sqrt(2),2)`.
The fixed static72 and dynamic/plugin76 assertions passed on the DUT, along with
BusyBox and private native/core-to-ARM32-ubusd supervision. An additional build
guard rejects a direct recursive call in the generic `fma` function.

Two fresh roots reproduce all5 runtime/BusyBox files and35 core ELF paths.
The accepted b05 RAM image is frozen and still contains the older libc. Its
successful wireless tests remain that image's evidence; they do not qualify
unexercised math paths. Integrating the correction requires a new image and
separate RAM-boot/lifecycle acceptance. No running libc was hot-replaced.

## Lua and Nixio

`tools/build_a64_soft_lua.py` copies cached, OpenWrt-patched Lua5.1.5 and Nixio
into a new owned root. It uses the matching double/int32 Lua number model and
the corrected soft-float base. Five ELF images close their DT_NEEDED and strong
dynamic symbols, contain no audited FP/SIMD register instructions, and have no
RPATH/RUNPATH. Source-file hashes are recorded. Two different-length fresh roots
produce identical hashes. No source download is needed.

The bounded Nixio build has TLS and shadow support disabled; it is not advertised
as feature parity with the installed package. Native curl supplies the separate
tested TLS slice. The original ARM32 Nixio remains installed.

The DUT runs `diagnostics/a64_soft_lua_test.lua` as source and native bytecode,
23 checks each: arithmetic, math/formatting, binary file round trips with partial
reads, sparse file positioning beyond4GiB, pipes, timestamps, coroutines, GC and
dynamic C-module loading. Its ordinary ARM32 Nixio C plugin is correctly rejected.

OpenWrt deliberately serializes Lua bytecode string lengths as `unsigned int`.
Matching Lua number models therefore permit the tested ARM32-generated bytecode
to run on this64-bit interpreter. An incompatible version header is rejected.
Portable bytecode does not imply C ABI compatibility.

## UCI, ubus and uloop

`tools/build_a64_soft_lua_bindings.py` adds these cached C bindings to the owned
Lua root. The explicit soft Lua include path and module install path prevent
host-side Lua detection or use of the SDK's ordinary AArch64 Lua library.
Its complete14-ELF closure has the same instruction, RPATH and dynamic-symbol
audits. `diagnostics/a64_soft_lua_bindings_test.lua` exercises a private UCI
configuration commit/unload/reload, a real two-process ubus RPC and a uloop timer.
The system ubus and UCI configuration are not modified.

The cached upstream Lua ubus encoder writes numeric values as integers even
though its decoder supports DOUBLE. An attempted fractional RPC exposed that
pre-existing wire-format limitation. The final fixture explicitly uses integer
RPC fields and a formatted fraction string. It does not claim fractional numeric
ubus transmission or silently change the upstream API.

## Reproduce

```sh
python3 tools/build_a64_soft_suite.py --root /tmp/soft-core-fixed
python3 tools/build_a64_soft_lua.py \
  --root /tmp/soft-lua --base-soft-root /tmp/soft-core-fixed
python3 tools/build_a64_soft_lua_bindings.py --root /tmp/soft-lua
```

Use a second set of fresh paths for an independent reproduction. No target
program is run during these builds. Hardware tests require a separate guarded
RAM deployment and cleanup. No ordinary AArch64 package compatibility, full
LuCI closure, complete Nixio API coverage or standard package upgrade support is
claimed. Native Go/C++ and a distinct package ABI/unified SDK remain open.

Lua retains its MIT license; Nixio retains Apache-2.0; the OpenWrt libraries and
patches retain their original notices. Build receipts identify cached source
files. Runtime artifacts and private device logs are excluded from publication.
